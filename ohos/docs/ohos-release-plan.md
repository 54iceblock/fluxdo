## 0. 一页纸摘要（给决策者）

**一句话**：工程已经「能构建、能安装、能跑」，但离「能提审」还差三件事——**发布证书、隐私合规体系、备案/授权**；其中**备案是唯一无法用人力压缩的外部等待**，也是最可能卡死整个国内上架计划的环节，必须在开工第一周就判定可行性。

### 0.1 五个关键判断

1. **发布证书是总闸**：App 备案要用发布证书的**公钥 + SHA1 指纹**〔已核实〕，所以「定稿发布证书」必须排在备案之前；证书不定，备案无法提交，上架无法开始。
2. **备案是硬门禁且周期最长**：服务器在中国大陆 + 上架应用市场 ⇒ 必须做 App 备案；周期约 **服务商初审 3–5 工作日 + 通管局 2–20 工作日 ≈ 5–25 个工作日**〔已核实〕。**但 FluxDO 没有自有服务端/域名（服务端是 linux.do），能否备案、以什么主体和域名备案，必须先做 Go/No-Go 判定**（见 R1）。
3. **隐私合规是最大工程量**：当前应用**完全没有**隐私政策/用户协议/首启同意门槛，且**启动即联网**（自动查 GitHub 更新）〔审计实测〕。这是华为审核的一票否决项，整改量约 **8–12 人日**，且必须留「同意前零联网 / 零权限」的录屏证据。
4. **站外更新必须整体下掉**：应用内检查更新指向 GitHub Releases 下载，华为明文禁止「从自有或第三方站点下载可执行组件 / 站外更新」〔条款已核实（旧版指南），鸿蒙版表述待核实〕；OHOS 版首版应改为「仅通过应用市场更新」。
5. **第三方 IP 授权是隐性红线**：FluxDO 是 linux.do 非官方客户端，使用其内容与名称/IP；审核走知识产权条款〔部分已核实〕，需准备**站方书面授权**或**去商标化的非官方声明**，并在商店描述、应用内「关于」页双处标注。

### 0.2 三条并行主线（不设硬日期，按门禁推进）

```
主线 A（外部，最长）：证书定稿 → App 备案(5–25 工作日) ──────────┐
主线 B（内部，最大）：隐私合规整改 + 工程整改 + 素材 ──────────────┼─→ 提审 → 审核 → 灰度 → 全量
主线 C（前置，最高风险）：备案可行性判定 + linux.do 授权 ──┘
```

### 0.3 建议相对节奏（仅参考，日期待立项后填）

| 相对周 | 里程碑 |
|---|---|
| W0 | G0 决策完成（备案路径结论、授权结论、主体/账号就绪）；G1 启动申请发布证书 |

## 1. 目标、范围与成功标准

### 1.1 目标

在华为应用市场（中国大陆）**公开发布** FluxDO HarmonyOS 7（API 26）版首个上架版本 **0.2.29**，用户可搜索、安装、更新；发布后具备可维护的版本迭代与合规复审能力。

### 1.2 范围（In scope）

| 项 | 决策 |
|---|---|
| 分发渠道 | 仅华为应用市场（AppGallery）中国大陆站 |
| 系统版本 | HarmonyOS 7 / API 26（`compatibleSdkVersion 26.0.0`，与现有真机 HBN-AL00 / 7.0.0.109 一致） |
| 设备类型 | 首版 **仅 phone**；tablet 保留声明但不作为首发验收对象（见 R5/P2） |
| CPU 架构 | 仅 **arm64** 单 ABI（现状 114.9 MB，双 ABI 204.8 MB 不上架） |
| 版本号 | 0.2.29 / versionCode 2026102016（以 `repo/pubspec.yaml` 为单一真源） |
| 商业模式 | 免费、无内购、无广告 SDK（现状如此） |
| 首版不做 | 海外 AppGallery、元服务、Push Kit 远端推送、https App Linking（需自有域名）、平板/2in1 专项适配、应用内自动更新 |

**Out of scope 的理由**：`http 深链需自有域名`〔已核实：App Linking 需自有域名部署 `/.well-known/applinking.json`〕；`远端推送需自建转发服务`（见 `docs/ohos-native-strategy.md` R7）；平板/折叠屏未做适配验证。

### 1.3 成功标准（Definition of Done）

1. 审核通过并**公开发布**，华为后台状态「已上架」，中国大陆可搜索/安装。
2. **全部 P0 清零**（见 §7 门禁清单与 §4 差距基线），0 次因同一原因被拒审。
3. 发布包为 **AGC 发布证书 + Release Profile** 签名，arm64 单 ABI，可重复构建。
4. 合规材料归档完整：隐私政策（版本号+URL+截图）、用户协议、第三方 SDK 清单、授权/软著材料、备案号、测试账号、审核说明。
5. 灰度期（≥3 天）无 P0/P1 线上问题，崩溃率与启动成功率达标（目标值在 G4 定基线）。

## 11. 附录

### 11.1 首版明确不做（Out of scope）与理由

| 不做项 | 理由 |
|---|---|
| 海外 AppGallery 同步首发 | 需单独主体/税务/语言与政策适配；国内优先 |
| Push Kit 远端推送 | 需自建转发服务 + AGC 权益审核，见 `docs/ohos-native-strategy.md` R7 |
| https App Linking | 需自有域名 + `/.well-known/applinking.json` + AGC 域名校验〔已核实〕，linux.do 域名不可控 |
| 平板/2in1/折叠屏专项 | 无适配验证证据，首发仅 phone 降风险 |
| 应用内自动更新 | 华为禁止站外更新/下载可执行组件；HAP 也不支持静默安装 |
| 元服务（Atomic Service） | 与当前应用形态不符 |

### 11.2 术语

- **AGC**：AppGallery Connect，华为应用市场后台（应用/证书/发布/质量/分析）。
- **App 备案**：工信部移动互联网应用程序备案，中国大陆上架前置。
- **HAP / APP Pack**：HarmonyOS 应用安装包 / 上架包集合。
- **Profile（.p7b）**：签名配置文件，绑定包名与证书，区分 debug（设备白名单）/ release。
- **App Linking**：HarmonyOS 的 https 深链机制，需域名校验。
- **CF**：Cloudflare（linux.do 站点前置防护）。
